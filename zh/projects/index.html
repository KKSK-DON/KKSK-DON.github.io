项目经历

几个围绕 AI 基础设施的项目，覆盖推理、分布式通信、训练性能和 CUDA 算子。

vLLM INT8 KV Cache 量化

个人 vLLM fork——PyTorch、vLLM v1 paged attention 与 KV cache 管理、lm-eval

  • 概述：负责 INT8 KV cache 动态与静态量化方案的设计与实现：分析 KV 数值分布与量化误差，选取 per-channel 粒度；用 PyTorch 搭建量化 PagedAttention 算子与测试，先以动态量化验证精度，再据此设计静态量化方案。动态方案在运行时统计 scale、读取 KV 时量化；静态方案离线校准并加载固定 scale，改造 vLLM 的 KV cache 分配与读写接口，实现写入时量化及 INT8 存储。
  • 精度：静态量化在 GSM8K 全量与 HumanEval 评测中精度与 BF16 基线持平；兼容 Chunked Prefill 与 Prefix Caching。
  • 容量：静态量化将每 token 的 KV 占用减半，同等显存下 KV cache 容量翻倍并提升 Prefix Caching 命中率。

多模态模型训练性能优化

torch.profiler、pinned memory + CUDA event、算子融合

  • 概述：对开源多模态多卡训练做性能分析与优化：用 torch.profiler 抓取 trace，定位并消除同步点、融合小算子、让通信与计算重叠；以基线与优化版 trace 对照验证。
  • 同步点消除：数据搬运的 H2D 拷贝改为 pinned memory + non_blocking，CPU 发完命令即返回；CPU 需读取的 GPU 结果先以 non_blocking 拷入 pinned memory，插入 CUDA event，到使用时再同步读取；前向中的 .item() 改为提前算好传入；每步 GPU 空闲减少约 8 ms。
  • 算子融合：将 RMSNorm、RoPE 替换为 Apex FusedRMSNorm 与 TransformerEngine FusedRoPE：单次 RMSNorm 从 8 个 kernel 降为 1 个（218.7µs → 35.7µs），RoPE 从 10 个降为 2 个；单步 kernel 数 21761 → 14008，逐元素小算子 GPU 时间 −30%。
  • 通信计算重叠：分析 all-gather 与计算的重叠，定位前向的 all-gather 被无依赖的多模态编码串行阻塞；将多模态编码移至独立 CUDA stream 使二者重叠，并用 event 在首次使用处同步保证准确性，每步节省约 3 ms。

MoE All2All Dispatch/Combine（对齐 DeepEP）

PyTorch distributed——专家并行、变长 all2all

  • 概述：熟悉 MoE 专家并行完整流程，基于 torch.distributed 的 all_to_all_single 从零实现 dispatch/combine 的 DeepEP 等效版本。
  • 通信：每层通信从参考实现的 5 次 all2all 优化到 3 次（1 次专家计数 + 2 次变长数据交换）：利用收发矩阵的转置对称性，返程 splits 等计数全部本地推导，不再重复通信。
  • 验证：在双卡 NVLink H100 上与 DeepEP V2 对比：combine 输出精度对齐；打开 DeepEP 的 deterministic 后，dispatch 也逐行对齐。

CUDA 高性能算子开发

CUDA C++——Nsight Compute

  • 概述：开发 LayerNorm/RMSNorm、GEMM、reduce 等 FP32 算子并在 H100 上逐级优化，以 cuBLAS 与 CPU 参考实现校验精度；按计算强度判断算子受带宽还是算力限制，用 Nsight Compute 分析带宽与算力利用率及瓶颈。
  • LayerNorm/RMSNorm：使用算子技能：树状归约 → warp shuffle 归约 → 两级归约；float4 向量化访存；寄存器缓存；带宽利用率 LayerNorm 63.8% → 81.3%，RMSNorm 46.5% → 81.7%。
  • GEMM：逐级优化：合并访存 → 共享内存分块 → 1D/2D thread tile 与寄存器复用 → float4 向量化读写 → 双缓冲；128×128 tile 下 FP32 算力利用率 58%，达 cuBLAS 的 75%。
